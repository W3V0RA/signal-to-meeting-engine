# Operating and recovery guide

Start with `npm run check` and the offline demo. Inspect research gaps and exact copy before any authenticated human decision. Keep external writes disabled until the separate live readiness scope has been explicitly approved and independently verified.

The local review command reads supplied research, stores an unapproved draft and prints evidence/writing gaps. `Engine.approve()` needs the human token, reviewer and all six checks. Technical release is separately issued only after the exact current context passes. No batch approval, digest link or Notion checkbox is an authorization channel in this implementation.

Follow-up planning produces three `needs_authoring` items with local-window due dates. Author each personally relevant touch from fresh sources and the real current thread. Follow-up sequence permission does not create copy or sender proof. Reconciliation is idempotent and does not revive cancellations. A scheduler must call the library later; no recurring task was installed by this repository.

Poll each active thread with the Gmail adapter and pass normalized events into authenticated ingestion. Delivery also performs a fresh identity/history/thread read before reservation. Plain-text replies stop the sequence; exact structured delivery-status bounces and unsubscribe intent suppress the route. Alternative recipient routes, HTML-only responses and mailbox-wide bounce correlation require explicit extension and testing. Treat an unsupported inbound format as a hold rather than evidence that the sequence may continue.

Use `dashboard(store)` for technical state and `learning(store)` for observed rates. The served dashboard is the latest fictional demo only. Confirm actual delivery from received artifacts and actual bookings from associated accepted Calendar events. Owner alerts remain pending work; no digest or immediate owner email is delivered automatically. No revenue metric is inferred from provider acceptance or booking.

When a send is uncertain, stop automatic retries. Inspect provider Sent and match the generated Message-ID, recipient, exact copy and timestamp. Preserve the held attempt and audit the review. There is no automatic reset/retry tool. A trusted reconciliation implementation must confirm provider acceptance or a demonstrably unsent outcome before any new authorization; if uncertain, keep the hold. An expired release requires a fresh evaluator check and cannot be bypassed by editing expiry.

Changing identity/configuration invalidates matching approvals/releases and follow-up policy. Changing copy through `draft()` clears approval and release; attempted copy cannot be overwritten. Refreshing source snapshots changes the unsent digest. New inbound revokes pending response approvals. Retain suppression across every migration and restore.

Back up durable state consistently and protect it as private business data. The reference audit is local and durable, but not cryptographically append-only. Do not commit runtime files or email bodies. Cost rows record supplied operation costs; external service/subscription billing must be reconciled separately. Learning recommends review and never raises caps or changes autonomy.
