# Writing and source attribution

The behavioral standard was distilled from the owner's private operating contract and its outcome-first addition to prior v2 guidance. No third-party skill text, customer example, claimed dataset, quantified lift or training assertion is included. Framework labels such as Before-After-Bridge, AIDA and Problem-Agitate-Solution are general writing concepts; no numerical performance benefit is promised. The fictional scenario illustrates one proposed workflow and makes no claim that it exists in a real business.

Before authoring, write a three-part brief: the verified observation, the plausible opportunity to investigate, and the smallest useful next step your business can honestly offer. Select a structure appropriate to the evidence. Use problem-focused language only where evidence establishes a problem. A published service or new job posting does not prove that internal work is broken.

Open with a concrete possible payoff, then connect it promptly to the supported company fact. Express inferred needs as questions or possibilities. Keep human review of dates, commitments and proposed changes explicit where relevant. Do not invent urgency, savings, customer results, a personal connection or an already-built sample.

The default greeting uses the verified person's first name, including through an independently verified shared or official free-mail business inbox. A business can opt into `sharedInboxGreeting: "neutral"` for routes explicitly classified as shared; those drafts use `Hi there,`. Neither greeting claims a shared address is personally owned. When a name is missing, drafts can use `Hello,` but release retains the named-contact research gap. A configuration change can invalidate an existing exact-copy approval or release and does not rewrite stored messages.

Default first-touch copy uses 50–80 words excluding greeting/signature/opt-out, short paragraphs, plain text and one final question. Subjects default to neutral Title Case. A business can configure sentence case, word and character ranges, including a 60–100-word, 3–6-word-subject experiment. Keep the accurate identity, website, postal address and opt-out separate from word count.

Review the last ten available drafts for recurring subjects, openings, question forms and rhythm. The code detects exact subject/opening/question repetition, not every semantic template or paragraph-rhythm pattern. Human review must cover those subtler issues; fewer available drafts limits comparison. Follow-ups should add fresh useful context. Responses should answer the actual inbound message and receive new exact-copy approval. No guilt-based breakup or fabricated proof belongs in a sequence.

Typed fact paragraphs are verified by exact source quote, not keyword overlap or unrestricted model judgment. A good citation never excuses another unsupported assertion. This conservative constraint can produce awkward copy; author an appropriate quote or leave a clear verification gap. Arbitrary paraphrase needs a separately evaluated source-to-claim implementation before it can clear transport.

By default, only an interested prospect's newly approved response may contain the booking link. The optional Google appointment experiment permits the configured link in initials and follow-up 3, never follow-ups 1 or 2. A current schedule identity check and separately reviewed duration are required for releases with that link. The response still requires verified interest and a fresh individual approval. Preserve historical messages and the original offer. A quality-passing draft is still unapproved, unsent and possibly blocked by evidence, permission or sender proof.
